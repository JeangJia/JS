JS 垃圾回收机制(Garbage Collection)

一、核心概念:什么是"垃圾"?

JS 中"垃圾"指 程序后续无法访问到的内存数据(如未被任何变量引用的对象、超出作用域的局部变量).

垃圾回收机制的核心:自动识别并回收"垃圾",释放内存,避免内存泄漏.

二、核心算法:引用计数(已淘汰)

1. 原理

给每个对象记录"被引用的次数",次数为 0 时自动回收.

2. 示例代码

// 引用计数示例
let obj = { name: "张三" }; // 引用计数 = 1
let obj2 = obj;            // 引用计数 = 2
obj = null;                // 引用计数 = 1
obj2 = null;               // 引用计数 = 0 → 引擎回收该对象

3. 致命缺陷:循环引用

两个对象互相引用,引用计数永远不为 0,导致内存泄漏.

// 循环引用导致内存泄漏(引用计数算法)
function testReferenceCountFn() {
    let a = {};
    let b = {};
    a.b = b; // a 引用 b
    b.a = a; // b 引用 a → 循环引用
}
testReferenceCountFn(); // 函数执行后,a/b 无法被回收(引用计数算法下)

三、核心算法:标记-清除(主流引擎采用)

主流引擎(Chrome V8、Firefox SpiderMonkey)均采用此算法,解决了循环引用问题.

1. 原理

① 标记阶段:从"根对象"(window/global、执行栈变量)出发,标记所有可访问的"活跃对象";

② 清除阶段:回收未被标记的对象(垃圾),释放内存.

2. 解决循环引用示例

// 标记-清除算法可回收循环引用对象
function testMarkSweepFn() {
    let a = {};
    let b = {};
    a.b = b;
    b.a = a;
}
testMarkSweepFn(); // 函数执行后,a/b 无法被根对象访问 → 标记阶段未被标记 → 清除阶段回收

四、常见内存泄漏场景(垃圾回收失效)

1. 意外的全局变量

function fn() {
    uname = "张三"; // 未声明 → 挂载到window → 全局变量不会被回收
}
fn();

2. 被遗忘的定时器/事件监听

// 定时器引用DOM → DOM无法被回收
let timerId;
let fakeBtn = { textContent: "测试按钮" }; // 模拟DOM对象

function testTimerLeak() {
    timerId = setInterval(() => {
        log.innerHTML += "定时器运行中...
";
        console.log(fakeBtn.textContent);
    }, 1000);
}

function clearTimer() {
    clearInterval(timerId);
    log.innerHTML += "定时器已清除 → fakeBtn可被回收
";
}

3. 闭包导致的内存泄漏

function outer() {
    let bigData = new Array(1000000).fill(0); // 大内存数据
    return function inner() {
        console.log(bigData.length); // 闭包引用 → bigData无法被回收
    };
}
const fn = outer(); // 只要fn存在,bigData就不会被回收
// 修复:fn = null; // 解除引用 → bigData可被回收

五、算法对比总结

| 算法类型   | 原理                 | 优点         | 缺点             | 主流引擎是否采用 |
|------------|----------------------|--------------|------------------|------------------|
| 引用计数   | 记录对象引用次数     | 实现简单     | 无法解决循环引用 | ❌ 已淘汰        |
| 标记-清除   | 标记活跃对象,清除未标记 | 解决循环引用 | 产生内存碎片     | ✅ 主流采用      |
核心总结:JS 垃圾回收是自动的,但开发者需避免内存泄漏(及时清除定时器、避免意外全局变量、合理管理闭包).
